## G0：治理基线

任务：

- 审查范围固定为 `AGENTS.md`、`DELIVERY_PLAN.md`、`QA_MATRIX.md`、`DECISIONS.md`、`CHANGE_CONTROL.md`；
- 固定三方一致决策机制；
- 固定截止时间、成功定义和禁止事项。

退出条件：

- 三位专家对治理文件全部无条件同意；
- 无相互冲突的事实来源；
- 材料性决策与例行实现边界清楚。

## G1：产品与交互契约

任务：

- 审查范围固定为 `PRODUCT_SPEC.md`；
- 完成目标用户、固定演示岗位、角色、页面动作矩阵和文案层级；
- 走查三分钟独立体验路径；
- 固定主流程、异常流程和视觉原则。

退出条件：

- 每个页面有明确任务、入口和出口；
- 每个按钮对应明确业务动作；
- “信息透明”和“模拟结算”表达不误导；
- 三位专家全部无条件同意。

## G2：状态、数据与安全

任务：

- 审查范围固定为 `DOMAIN_AND_DATA.md`，并跨文件检查与产品、QA的一致性；
- 固定实体、字段、状态机和角色操作权限；
- 固定金额、名额、过期、重复报名和重置规则；
- 固定 Anonymous Auth、RLS 和 RPC 边界。

退出条件：

- 所有合法/非法跳转均可枚举；
- 数据结构支持多校园和未来正式登录；
- 浏览器不能任意修改状态或金额；
- 三位专家全部无条件同意。

G0–G2 期间不得编写业务代码。

## G3：工程骨架与云端连通

任务：

- 创建 React + Vite + TypeScript 项目；
- 建立页面层、业务层和数据访问层；
- 增加 `.env.example`、`.gitignore` 和 migration 目录；
- 配置 Supabase client、匿名身份和基础迁移；
- 推送 GitHub，触发 Vercel 自动部署；
- 配置 SPA rewrite。
- 记录中国大陆无VPN到当前托管的真实连通结果；依据D-020，G3保留该外部托管阻塞但不阻塞派生feat分支上的G4–G6实现，且不得合并main。

退出条件：

- TypeScript、ESLint、测试和 production build 通过；
- Vercel 根页面和直接子路由均返回有效页面；
- Supabase 可读取一条测试数据；
- 公开仓库不存在密钥；
- 手机和 PC 没有横向溢出。
- 大陆无VPN直连失败必须保留DNS、443、HTTPS、网络、URL和是否使用代理的事实；不得把VPN/代理环境成功写成直连通过。
- 依据D-020，G3保持外部托管可达性阻塞，但允许G4–G6在派生feat分支推进；不得因此合并main或宣称Production已发布。
- G7至少测试Production短域名和一个经批准的备用托管候选；迁移区域或托管仍须提交材料性变更。

- 重复报名和非法跳转被阻止；
- 重置仅影响当前会话。

## G5：完整业务生命周期

任务：

- 招聘方录入实际工时并确认完工；
- 数据库自动计算金额并生成待结算记录；
- 招聘方在结算处理页确认 Demo 模拟结算；
- 学生端显示完整时间线与模拟金额；
- 增加 3–5 条班次、夜班补贴、时薪主流程和日薪样例；
- 完成筛选、比较和直招信息展示。

退出条件：

- `待招聘方确认（pending）→报名已确认（confirmed）→工作已完成（completed事件）→待模拟结算（pending_settlement）→已结算（Demo模拟，settled_demo）` 全程稳定；
- 状态、事件、名额和金额一致；
- 已结算始终带模拟标识；
- 不能跨级推进状态。
