# 三分钟演示脚本

适用链接：[已验证发布部署](https://campus-gig-platform-dsuy15830-campus-gig-platform.vercel.app)

## 开始前

- 使用一个浏览器窗口完成演示，同一窗口中的学生端与招聘方端读取同一匿名会话数据。
- 首次打开等待云端会话和五条岗位加载完成。
- 点击右上角“重置 Demo”→“确认重置”，避免上一次演示状态影响本次路径。
- 所有数据均为合成演示数据；“已结算”仅代表 Demo 模拟结算。
- 部分中国大陆无 VPN 网络可能无法直连 `vercel.app`；若 15–20 秒仍未出现应用壳，请更换到可访问 Vercel 与 Supabase 的网络环境。

## 00:00–00:45：学生做岗位决策

1. 保持“学生端”，进入“找零工”。
2. 观察 J-01“入库分拣”：匹配周六 14:00–19:00、约 0.3 公里、12元/小时、预计60元。
3. 给 J-01、J-02 各点击“+ 加入比较”，再点击“比较已选岗位”。
4. 对比白班时薪、夜班补贴、预计金额和结算条件，打开 J-01“查看详情”。
5. 在详情页快速展示招聘主体、实际用工地点、工资支付主体和三类收费项。

产品观察点：产品不是用不可解释的“可信度分”代替判断，而是逐项披露可核对证据。

## 00:45–01:10：学生报名

1. 点击“立即报名”。
2. 在确认弹层核对演示学生身份与可工作时间，点击“确认报名”。
3. 页面进入“我的报名”，状态为“待招聘方确认”，时间线出现第一条报名事件。

产品观察点：成功报名后 J-01 名额只扣减一次；重复请求不会产生第二条报名。

## 01:10–01:40：招聘方确认

1. 点击顶部“招聘方端”。
2. 进入“报名处理”，打开 J-01 的“进入确认”。
3. 点击“确认报名”。
4. 页面显示“报名已确认”，当前可处理动作变为核定实际工时。

产品观察点：角色切换不创建第二套数据；双方读取同一条 Supabase 报名。

## 01:40–02:25：完工与数据库计价

1. 在“核定实际分钟”输入 `270`。
2. 点击“确认完工并生成待结算”。
3. 观察页面进入“待模拟结算”，然后点击“查看模拟结算记录”。
4. 核对数据库计算金额 ¥54，点击“确认 Demo 模拟结算”。

产品观察点：一次数据库事务写入“工作已完成”和“待模拟结算”事件、计算金额并创建唯一结算记录；前端不提交最终金额。

## 02:25–03:00：学生回读闭环

1. 切换“学生端”→“我的报名”。
2. 核对终态“已结算（Demo模拟）”、核定工时270分钟和最终模拟金额 ¥54。
3. 展示完整时间线：

```text
待招聘方确认 → 报名已确认 → 工作已完成 → 待模拟结算 → 已结算（Demo模拟）
```

4. 刷新页面，确认状态、金额和事件仍从云端恢复。

## 可选异常支线

异常支线应在重新“重置 Demo”后单独演示，不要插入三分钟主流程。

### 学生取消

学生报名 J-01 后，在招聘方确认前进入“我的报名”→“取消报名”。失败时真实 pending 状态保留；成功后进入“报名已取消”终态并只释放一次名额。

### 招聘方拒绝

学生报名后切换招聘方，在 pending 阶段点击“拒绝报名”。空原因不能提交；填写原因后学生端会显示相同拒绝原因，报名进入只读终态。

### 岗位边界

- J-04 用于展示“已满”不可报名；
- J-05 用于展示“已过期”不可报名；
- J-02 展示夜班补贴；
- J-04 同时提供日薪计价样例。

## 故障处理

- 如果页面显示“云端连接失败”，点击“重新连接”或刷新；错误不会伪造为成功状态。
- 如果演示数据不是初始状态，点击“重置 Demo”。重置只影响当前匿名浏览器会话。
- 如果 `vercel.app` 在当前网络超时，换用可访问 Vercel/Supabase 的网络；不要反复提交业务按钮。
