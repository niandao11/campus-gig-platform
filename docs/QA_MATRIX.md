# 交付与质量验收矩阵

状态：G0–G2 验收基线已批准；G3 起按阶段补充执行证据。

## 1. 主流程

| ID | 场景 | 预期结果 |
|---|---|---|
| F-01 | 学生浏览开放岗位 | 显示班次、距离、计价、预计收入和结算规则 |
| F-02 | 学生提交有效报名 | 创建一条当前会话报名，状态显示“待招聘方确认”，名额减少 |
| F-03 | 招聘方确认报名 | 同一条报名显示“报名已确认”，双方时间线一致 |
| F-04 | 招聘方核定实际工时并完工 | 写入已完成事件，自动生成待结算记录和金额 |
| F-05 | 招聘方在结算处理页确认模拟结算 | 显示“已结算（Demo模拟）”，学生端可见金额和完整时间线 |
| F-06 | 刷新或角色切换 | 数据从云端恢复，不回退、不丢失 |
| F-07 | 重置当前 Demo | 仅当前会话恢复基线，岗位模板不被删除 |

## 2. 状态与异常

| ID | 场景 | 预期结果 |
|---|---|---|
| S-01 | 待确认直接跳到已结算 | 数据库拒绝，前端显示可理解错误 |
| S-02 | 重复报名同一岗位 | 被阻止，不重复扣减名额 |
| S-03 | 报名已满岗位 | 按钮不可用，数据库再次拒绝 |
| S-04 | 报名过期岗位 | 按钮不可用，说明岗位已过期 |
| S-05 | 学生取消 `pending` 报名 | 状态和事件更新，名额只释放一次 |
| S-06 | 学生尝试取消 `confirmed` 或之后报名 | UI不提供操作，RPC拒绝，状态和名额不变 |
| S-07 | 招聘方在 `pending` 拒绝且填写原因 | 进入终态，学生端看到理由和下一步，名额只释放一次 |
| S-08 | 招聘方拒绝时未填写原因 | 阻止提交，不改变状态 |
| S-09 | 完工工时无效 | 拒绝零、负数、非整数或大于计划分钟的工时 |
| S-10 | 重复点击状态按钮 | 操作幂等，不生成重复事件或结算记录 |

## 3. 金额与岗位

| ID | 场景 | 预期结果 |
|---|---|---|
| M-01 | 普通时薪岗位 | 按核定分钟和有效时薪正确计算 |
| M-02 | 夜班岗位 | 有效时薪包含夜班补贴，说明清楚 |
| M-03 | 日薪岗位 | 使用固定日薪，不重复乘以时长 |

| M-06 | 舍入样例：1200分/小时×61分钟 | 结果为1220分，按四舍五入到分计算 |

## 4. 数据与安全

| ID | 场景 | 预期结果 |
|---|---|---|
| D-01 | 匿名会话首次进入 | 获得无感身份，不要求输入账号密码 |
| D-02 | 读取公开岗位 | 仅暴露允许的校园、招聘方和岗位字段 |
| D-03 | 浏览器直接修改状态/金额 | RLS/RPC 边界阻止未授权写入 |
| D-04 | 检查仓库与构建产物 | 不含数据库密码、token或service_role key |
| D-05 | 重置 Demo | 只重置当前匿名会话数据 |
| D-06 | 云端故障 | 页面显示错误和重试，不伪造成功状态 |

## 5. 响应式与可用性

至少验收以下视口：

- 375×812；
- 390×844；
- 768×1024；
- 1440×900。

通用要求：

- Chrome、Edge 最新稳定版主流程一致；
- 无横向滚动、按钮遮挡和文本截断；
- 主要触控目标不小于 44px；
- 角色、状态、下一步和 Demo 标签始终可识别；
- 加载、空数据、错误和成功反馈清楚；
- 基本键盘导航可用。

## 7. 阶段证据

证据要求按阶段区分：

| 阶段 | 必需证据 |
|---|---|
| G0 | 文档版本/哈希、冲突检查、三方治理票决 |

每份执行证据记录环境、执行时间、执行者、结果和已知限制；G0–G2 不要求不存在的构建或部署证据。

### G3 无 VPN 冒烟判定

- 普通宽带和手机网络分别连续3次测试 Vercel 页面、Anonymous Auth 与 Supabase 基础读写。
- 零阻塞失败才通过；记录 URL、构建 SHA、网络、时间、首屏与首个数据耗时。
- 每次应用壳首页须在10秒内可见，Anonymous Auth与首个Supabase数据须在20秒内完成；超时、HTTP/网络/Auth错误或需要人工重试均判定为阻塞失败。
- 若失败，标记发布阻塞；区域迁移或备用托管须走材料性变更。

## 8. 补充隔离与边界测试

- 两个匿名会话的班次名额、报名、事件和重置互不影响。
- 在 `pending`、`confirmed`、`pending_settlement`、`settled_demo` 分别执行重置，均恢复当前会话基线。
- 重置后学生可用时间必须与新 J-01 班次的周六14:00–19:00一致。
- 多标签页或重复点击不会产生重复报名、事件或结算记录。
- Asia/Shanghai 周末边界计算正确，过期样例与开放样例可稳定复现。
- 在周六00:00、13:00、23:59访问时，J-05仍明确为严格过去的已过期样例；J-01的报名截止和学生可用时间与同一周六日期一致。
